# 阿奇索 × 拼多多激活码自动发货接口草案

状态：待联调。本文中的域名、密钥及退款通知来源尚待确认；在服务部署并通过验收前，不可将示例地址作为可用接口交给阿奇索。

## 对接范围

- 供货方：研刷通；销售渠道：拼多多；阿奇索负责触发采购并向买家交付激活码。
- 商品：小程序内启用且可核销的课程、套餐计划、整类课程套餐。积分、优惠券、代理身份码不在本接口销售。
- 结算：商家在研刷通预充值，采购时按独立设置的供货价扣款。拼多多售价与供货价分别维护。
- 采购和退款以稳定的拼多多订单明细号为依据。退款确认后，待使用码作废；已核销码作废并撤销该码授予的权益，返还原采购金额至商家预充值余额。

## 域名与路径

基础地址：`https://<待确认的阿里云接口域名>/api/partner/agiso/v1`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/purchase` | 采购激活码；同一订单明细号重试返回原结果 |
| `POST` | `/purchase/query` | 按订单明细号查询采购结果 |
| `POST` | `/refund` | 已确认退款后撤销权益并退回商家预充值余额 |
| `POST` | `/refund/query` | 按退款单号查询处理结果 |

接口使用 HTTPS。阿奇索应在联调时确认能配置以下请求字段及鉴权头。密钥只在双方后台交换，不写入本文件。若阿奇索不能计算约定签名，双方需按其实际支持的鉴权机制修订协议，再开放公网入口。

## 鉴权草案

请求头：`X-Merchant-Id`、`X-Timestamp`、`X-Nonce`、`X-Signature`。

签名内容：`HTTP_METHOD + "\n" + PATH + "\n" + TIMESTAMP + "\n" + NONCE + "\n" + SHA256(RAW_BODY)`；使用该商家独立密钥执行 HMAC-SHA256，输出小写十六进制。时间戳为 Unix 秒，允许前后 300 秒；同一商家的 nonce 在窗口内不得重复。签名细节以阿奇索配置能力和联调结果为准。

## 商品编码与价格

| `sku` 格式 | 激活目标 | 售卖条件 |
| --- | --- | --- |
| `course:<id>` | 单课程 | 课程启用、非免费、允许核销 |
| `package:<plan_id>` | 套餐计划 | 计划与所属套餐均启用 |
| `category_bundle:<category_id>` | 整类课程套餐 | 分类启用且套餐购买入口开启 |

在研刷通后台维护拼多多商品规格与 `sku` 的映射及每 SKU 供货价。采购时以服务端供货价为准，并将成交单价保存到采购单；退款使用该价格快照。商品下架不会改变已售激活码和原订单金额。

## 采购接口

`POST /purchase`，`Content-Type: application/json`。

```json
{
  "external_order_id": "PDD_ORDER_001",
  "external_order_line_id": "PDD_ORDER_001_SKU_01",
  "sku": "course:123",
  "quantity": 1
}
```

成功返回：

```json
{
  "success": true,
  "code": "OK",
  "data": {
    "purchase_order_id": "PH_A_001",
    "external_order_line_id": "PDD_ORDER_001_SKU_01",
    "status": "delivered",
    "unit_price": "20.00",
    "total_amount": "20.00",
    "items": [{ "item_index": 1, "activation_code": "EXAMPLEONLY12" }]
  }
}
```

每件商品返回一枚激活码，`items` 数量必须等于 `quantity`。成功仅表示研刷通已扣商家余额并分配激活码，不表示阿奇索已向拼多多买家发货。以 `(merchant_id, external_order_line_id)` 作为唯一幂等键；同号同参数返回原激活码，同号不同 SKU 或数量返回 `ORDER_CONFLICT`。余额不足返回 `INSUFFICIENT_BALANCE`，商品不可售返回 `SKU_UNAVAILABLE`。失败不得扣款或出码。

`POST /purchase/query` 请求体为 `external_order_line_id`；返回原采购状态及已分配激活码。调用采购接口超时后先查询原单；查询仍无法确定时，使用相同订单明细号重试，不得创建新订单号。查询接口不得产生扣款、出码或对象存储请求。

## 退款接口

退款触发源待确认：只接受拼多多退款**已成功**的可信通知或经商家授权的后端操作；买家仅申请退款时不得撤销权益或退回预充值余额。阿奇索如不能推送退款成功事件，需要另行接入拼多多官方售后消息，不允许通过高频扫描全量订单判断退款。

`POST /refund`：

```json
{
  "external_refund_id": "PDD_REFUND_001",
  "external_order_line_id": "PDD_ORDER_001_SKU_01",
  "item_indices": [1],
  "refund_status": "success"
}
```

`item_indices` 指定退款的采购件序号，可用于部分退款；整笔退款则列出全部序号。以 `(merchant_id, external_refund_id)` 保证退款幂等，并拒绝超出已采购数量的重复/交叠退款。对每件退款商品，在同一数据库事务中锁定采购项、作废激活码、撤销该码产生的课程或套餐权益、按原单价返还预充值余额、写入不可修改的余额流水及退款记录。重复通知返回首次结果。已核销码的实际核销用户可能与拼多多买家不同：只撤销该码对应的权益；其他有效购买、其他激活码、免费课程权益仍保留。已下载到本地的文件无法收回，退款仅阻止后续服务端访问。

`POST /refund/query` 请求体为 `external_refund_id`，返回原退款处理状态与本次退回商家余额的金额，不返回小程序用户个人信息。

## 实施前提与验收

1. 取得阿里云服务器公网 IP/实例、可用域名及 DNS 管理权限，部署 HTTPS 入口。现有阿里云文件预览工作节点不承接业务 API；是否共机需要先确认资源容量、隔离和数据库连通。
2. 与阿奇索确认拼多多订单明细号、商品规格编码、数量、退款成功通知、签名及响应映射。按最终能力调整本协议与接口配置。
3. 为课程、套餐、整类套餐建立激活码级权益归因。现有套餐订阅会合并多次购买，不能直接用于按单撤销；历史权益迁移须保持已有用户权限。
4. 采购、退款、余额流水和权益变更均需事务及唯一约束。激活码用加密安全随机数生成，避免重复或可预测。
5. 上线前关闭自动采购，手动执行小额联调：正常单、并发重复单、超时重试、余额不足、部分退款、已核销退款、套餐叠加后退款、退款后重复通知；检查数据库、真实服务与拼多多发货结果。
6. 无待处理订单时不产生外部请求。阿奇索官方帮助中心目前列出直充直采下单调用约 5 奇豆/次；按每天 `N` 单、每单 `R` 次采购调用估算，月调用量为 `N × R × 30`，奇豆约为 `N × R × 30 × 5`，另核对补单量、短信、阿里云实例和公网带宽费用。正式计费以阿奇索实际套餐和账单为准。
