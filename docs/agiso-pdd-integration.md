# 阿奇索 × 拼多多激活码供货接口

状态：接口合同与代码已准备，公网地址以部署及联调验收结果为准。阿奇索只需调用以下三个接口；充值、定价和商品启用由研刷通内部管理。

## 对接约定

- 使用拼多多稳定的**订单明细号**作为 `order_no`。一个明细号购买一件商品、领取一枚激活码；购买多件时，每件需有不同的稳定明细号。
- `product_name` 必须与我方提供的唯一名称完全一致，区分大小写、空格和标点，例如 `课程名 [C123]`、`套餐区 - 月卡 [P45]`、`分类名 [B67]`。不能只传“月卡”。
- 商品包括小程序已启用、收费的课程、套餐计划和整类课程套餐。供货价与拼多多售价独立设置；未设置供货价或未启用的商品不会发码。
- 阿奇索在拼多多退款**成功**后调用撤销接口。接口不接入拼多多回调，也不主动扫描订单。
- 金额单位为人民币元，保留两位小数。采购扣预充值余额，撤销按采购时供货价退回。

## 连接信息

计划接口域名：`https://agiso.ltzm.me`。**DNS、HTTPS、服务和真实请求验收完成前，不能作为可用地址交付。**

接口使用 `POST`、`Content-Type: application/json`、UTF-8。请求及响应均为 JSON，不接受 URL 查询参数。请求体最大 8 KiB。所有响应带 `X-Request-Id`。

| 路径 | 作用 |
| --- | --- |
| `/auth` | 换取短期访问令牌 |
| `/issue` | 按唯一商品名和订单明细号采购一枚激活码 |
| `/revoke` | 按原订单明细号作废激活码并退回预充值余额 |

## 1. 鉴权

`POST /auth`

```json
{"client_id":"agiso-partner-id","client_secret":"双方线下安全交付的密钥"}
```

成功返回（令牌默认有效 300 秒）：

```json
{"success":true,"code":"OK","data":{"access_token":"<token>","token_type":"Bearer","expires_in":300},"request_id":"<id>"}
```

后续两个接口带 `Authorization: Bearer <access_token>`。令牌过期时重新调用 `/auth`。密钥和令牌不得放入 URL、商品备注或公开文档。

## 2. 采购激活码

`POST /issue`

```json
{"product_name":"示例课程 [C123]","order_no":"PDD-ORDER-001-ITEM-01"}
```

成功返回：

```json
{"success":true,"code":"OK","data":{"order_no":"PDD-ORDER-001-ITEM-01","product_name":"示例课程 [C123]","status":"issued","activation_code":"AG<随机激活码>","supply_price":"20.00","balance":"980.00","issued_at":"2026-09-28T08:00:00.000Z","revoked_at":null},"request_id":"<id>"}
```

同一商户用相同 `order_no` 和 `product_name` 重试，只返回首次生成的激活码，不重复扣款。同一订单号改传其他商品返回 `ORDER_CONFLICT`；订单已撤销后不能再次发码。采购超时用**原订单号**重试，不能换号。余额不足返回 `INSUFFICIENT_BALANCE`，商品未配置或未启用返回 `PRODUCT_NOT_FOUND`。

## 3. 撤销激活码

`POST /revoke`

```json
{"order_no":"PDD-ORDER-001-ITEM-01"}
```

成功返回 `status: "revoked"`、原激活码、原供货价、退款后的预充值余额与 `revoked_at`，其余字段与采购成功响应相同。同一订单号重复撤销返回原结果，不再次退款。找不到原订单返回 `ORDER_NOT_FOUND`。

未核销码立即作废。已核销码保留核销记录用于审计，同时撤销这枚码授予的课程、套餐时长或整类课程权限；同一用户的其他有效订单、激活码、免费课程权益仍保留。归因数据缺失或冲突时返回 `ENTITLEMENT_INCONSISTENT`，本次作废和退款均回滚，需人工处理。已下载到用户设备的文件不能远程删除，但后续服务端访问权限会被撤销。

## 失败响应与重试

失败统一格式：

```json
{"success":false,"code":"INSUFFICIENT_BALANCE","message":"预充值余额不足","request_id":"<id>"}
```

`400` 参数错误；`401` 凭证或令牌错误；`404` 商品或订单不存在；`409` 余额不足、订单冲突或权益数据不一致；`413` 请求体过大；`415` Content-Type 错误；`429` 限流；`500/503` 服务异常。网络超时或 `5xx` 使用相同订单号退避重试。业务 `4xx` 不应盲目换号重试。阿奇索需控制谁有权在确认退款成功后调用 `/revoke`。

## 我方配置与交付

我方生成带 `[C/P/B + ID]` 的唯一商品名清单，供阿奇索与拼多多商品保持一致。首次同步不会自动启用商品、设置供货价或充值。供货价、可售状态、预充值资金和商户密钥经内部核对后单独配置。接口服务只按请求执行数据库事务，空闲时不扫描云资源。

上线前用测试商户核对：鉴权、商品名精确匹配、余额不足、并发重复采购、超时原单重试、未核销撤销、已核销课程/套餐/整类套餐撤销、重复撤销、其他权益保留、账本借贷一致，再检查真实 HTTPS 和现有小程序核销链路。阿奇索官方文档目前说明其直充直采下单接口可能按调用收费；以每件 `1` 次采购、每月 `N × 30` 件估算调用量，另计重试和联调调用，费用以阿奇索实际计费和账单为准。
